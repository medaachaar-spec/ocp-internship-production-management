Creation additionally sets `Status` to `InProgress`, which is confirmed by the functional scenario, the SQL check constraint, and existing rows. It does not use the database default `Completed` because that default contradicts the documented initial voyage state.

The following fields are protected:

- identity `TripID` is generated by SQL Server;
- `CreatedAt` is generated by `sysutcdatetime()`;
- `Status` is preserved during editing because transitions are reserved for Part 3;
- navigation properties and dependent `TruckStop`/`QualityResult` collections are never mapped from HTTP input.

## Important discrepancies

- The real table is `WorkShift`; older material sometimes says `Shift`.
- `TripDate` differs from the calendar date of `StartTime` in 162 existing rows, so deriving it would corrupt operational semantics.
- SQL permits zero tonnage, while validated UI/UX requires a positive supplied tonnage. The application applies the stricter documented rule.
- SQL defaults `Status` to `Completed`, while the validated creation scenario requires `InProgress`. Creation sets `InProgress` explicitly.
- The frozen schema has no author, modification date, validation state/date, business voyage code, or rowversion.

## Architecture

Application:

- `CreateTripCommand` and `UpdateTripCommand` contain only authorized fields;
- `TripEditData` provides safe edit projection data;
- `TripFormOptions` provides presentation-neutral reference choices;
- `TripWriteResult` exposes success, validation, missing-row, concurrency, and persistence outcomes;
- `ITripWriteService` defines the write boundary.

Infrastructure:

- `TripWriteService` validates fields and every foreign key;
- form options use ordered, no-tracking active-reference queries;
- creation constructs a generated `Trip`, calls `AddAsync`, and saves;
- editing loads the tracked entity and assigns each permitted property individually;
- generated fields and status are never overwritten;
- expected persistence errors are logged and returned as safe French messages.

Web:

- dedicated nullable input models provide reliable required-field validation;
- `FlexibleDecimalModelBinder` accepts HTML dot and French comma decimal separators without accepting ambiguous thousands notation;
- `TripsController` remains protected by `CanManageTrips` and contains thin GET/POST actions;
- POST actions use antiforgery and Post/Redirect/Get;
- route and input IDs must match on Edit;
- list state is preserved through Create, Edit, Details, cancel, and success redirects;
- Razor forms use the existing Bootstrap design, accessible labels, validation summary, field messages, required indicators, and duplicate-submit protection.

## Validation

Input-model and service validation both enforce:

- required operational date, start timestamp, and five foreign keys;
- positive identifiers;
- selectable/active foreign references;
- end timestamp greater than or equal to start timestamp;
- nullable positive tonnage within `decimal(10,2)` capacity;
- nullable observation limited to 500 characters.

Status is not posted by either form. Creation sets only `InProgress`; editing preserves the stored value and exposes no status selector.

## Authorization and security

- the existing `CanManageTrips` policy remains unchanged;
- AgentProduction and Superviseur are authorized;
- AgentQualite and anonymous users are denied by existing cookie/policy behavior;
- both POST actions use `ValidateAntiForgeryToken`;
- generated `Trip` is never an action parameter;
- route ID mismatch returns Bad Request before service execution;
- only generic French persistence errors reach ModelState;
- Razor output remains encoded and no `Html.Raw` is used;
- no connection value, credential, stack trace, or SQL error is rendered.

## Concurrency behavior

No rowversion or configured concurrency token exists. The service catches `DbUpdateConcurrencyException`, including deletion races, and returns a safe conflict message. It cannot detect two ordinary overlapping edits without a forbidden schema change. Last successful save therefore remains a documented limitation.
